# Automatic inbound call capture

Riley v9 uses LogLead v5 at authenticated POST /api/vapi/lead. Its standard credential sends Authorization: Bearer with the existing VAPI_WEBHOOK_SECRET. Assistant status/completion events POST /api/vapi/events with the matching x-vapi-secret header. Both require an exact constant-time secret comparison. The old Vapi intake branch of public /api/leads returns 410; website forms remain separate.

Only the configured Riley inbound-phone-call envelope is accepted. Provider call ID, caller number, call type and assistant ID correlate call and tool records. Confirmed callback and caller ID remain distinct. Withheld callers are labelled unavailable. Unknown calls remain unqualified activity; a call is not automatically a qualified sales lead. Existing contact stage is preserved.

On completion, callback verification uses authenticated provider roles: a caller states one US number, the bot repeats identical digits and asks for confirmation, the caller explicitly agrees, and a successful LogLead result identifies the same lead. A model digit typo is corrected before the alert. Ambiguous replies, inconsistent read-backs, oversized digit sequences, missing success markers and unrelated lead IDs do not overwrite contacts. The safeguard covers ten-digit US numbers or a leading country code 1.

The worker alerts the existing EMAIL_TO recipient after completion, or after an ended-status fallback delay of sixty seconds. SMTP failures retry at 5/10/20/40/60 minutes, with six attempts maximum. Provider acceptance is distinct from inbox delivery. Locks and idempotent events prevent ordinary duplicates, but a crash after SMTP acceptance and before database commit can cause a retry: delivery is at least once, not an absolute exactly-once guarantee. Message-ID is stable per call/callback. A confirmed callback correction after an accepted alert queues one marked correction with a distinct Message-ID.

The portal shows awaiting-completion, queued, retry-pending, failed and provider-accepted states with call IDs. Riley records callbacks; live owner transfer is not configured. Calls that never reach Vapi require Twilio logs for diagnosis. Twilio automatic opt-out replies are not duplicated by the worker.
